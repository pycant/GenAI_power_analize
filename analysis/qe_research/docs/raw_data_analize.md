原始数据（raw.json）包含了实验过程中最精细的记录，包括高时间分辨率的功耗、资源使用时间序列以及细粒度的事件标记。对这些数据进行可视化和分析，可以揭示汇总数据无法呈现的动态行为和微观特征，为深入理解模型能效提供关键洞察。

以下是针对 raw.json 数据建议进行的可视化和分析方向，按分析维度组织（在绘制前先1组织好文件结构，尽量清晰，色系可以采用Viridis 色标，不做强制要求）：

---

## 一、时间序列分析

### 1. 功耗与资源使用曲线
- **可视化**：绘制 GPU 功率（`gpu_power_w`）、GPU 利用率（`gpu_util`）、显存使用（`gpu_mem_mb`）、CPU 使用率（`cpu_percent`）（这里可以不画cpu因为模型均是在显卡上运行的）随时间的变化曲线。
- **叠加事件标记**：在曲线上标注 `inference_start`、`first_token`、`inference_end` 等事件，区分 Prefill 和 Decode 阶段。
- **目的**：
  - 观察 Prefill（处理输入）和 Decode（生成 token）阶段的功耗差异（Prefill 通常计算密集，Decode 访存密集）。
  - 识别功耗峰值出现的时间点（是否在首 token 附近）。
  - 验证模型加载后功耗是否稳定，是否存在异常波动。

### 2. 多轮对话的功耗分解（若 `per_turn_monitoring=True`）
- **可视化**：堆叠柱状图显示每轮对话的能耗（`gpu_energy_j`）和耗时。
- **目的**：分析对话轮次增加对能耗和延迟的影响，识别是否有累积效应。

---

## 二、首 token 延迟（TTFT）分析

### 3. TTFT 分布
- **可视化**：直方图或箱线图展示所有实验的首 token 延迟（从 `inference_start` 到 `first_token` 的时间差）。
- **目的**：
  - 评估模型对用户输入的响应速度。
  - 比较不同模型、量化方式、任务类型对 TTFT 的影响。
  - 识别极端值（可能因硬件调度引起）。

### 4. TTFT 与输入长度的关系
- **可视化**：散点图，横轴为输入提示词长度（可从对话记录中计算），纵轴为 TTFT，按模型/量化着色。
- **目的**：验证 TTFT 是否随输入长度线性增长，不同模型的斜率差异。

---

## 三、逐 token 生成延迟分析

### 5. Decode 阶段每 token 延迟（TPOT）分布
- **可视化**：箱线图或小提琴图展示所有 token 的生成延迟（可从相邻 `first_token` 到 `inference_end` 之间估算平均 TPOT，或若事件记录了每个 token 的时间则更细）。
- **目的**：
  - 比较不同模型的生成速度稳定性。
  - 观察是否存在长尾延迟（某些 token 生成特别慢）。

### 6. 生成延迟随时间的变化
- **可视化**：将 Decode 阶段的延迟按 token 序号绘制折线图，观察延迟是否随生成长度增加而增加（如因 KV 缓存增长）。
- **目的**：检测模型是否存在生成后期性能衰减。

---

## 四、能耗分解与效率

### 7. 每轮对话能耗占比
- **可视化**：饼图或百分比堆积柱状图，显示每轮能耗占总能耗的比例。
- **目的**：识别能耗主要消耗在哪一轮，是否首轮更耗能。

### 8. 能耗与生成 token 数的关系
- **可视化**：散点图，横轴为每轮生成的 token 数，纵轴为该轮能耗（`gpu_energy_j`），拟合回归线。
- **目的**：验证能耗是否与 token 数呈线性关系，不同模型的斜率（即每 token 能耗）差异。

### 9. 空闲功耗与工作功耗对比
- **可视化**：利用 `baseline_raw` 的空闲数据，绘制空闲功率水平线，叠加实验期间的功率曲线，直观展示增量功耗。
- **目的**：验证 `derived_metrics.P_inc` 计算的合理性，并观察空闲功耗是否稳定。

---

## 五、资源使用模式

### 10. 显存使用随时间变化
- **可视化**：折线图显示 `gpu_mem_mb` 随时间变化，叠加事件标记。
- **目的**：观察显存分配模式（是否在 Prefill 阶段分配，Decode 阶段平稳），识别是否有内存泄漏（使用结束后未释放）。

### 11. GPU 利用率与功耗关系
- **可视化**：散点图，横轴为 GPU 利用率（`gpu_util`），纵轴为功率（`gpu_power_w`），按阶段（Prefill/Decode）着色。
- **目的**：分析利用率与功耗的相关性，验证高利用率是否对应高功耗。

### 12. 温度对功耗的影响
- **可视化**：双 Y 轴图，一条线为功率，另一条线为温度（`gpu_temp_c`），观察温度升高是否导致功耗变化（或因降频引起功率下降）。
- **目的**：评估散热条件对能效的影响，确认实验环境是否稳定。

---

## 六、事件驱动的微观分析

### 13. 事件时间线
- **可视化**：甘特图显示每个实验的事件时间线（如 inference_start, first_token, inference_end），按轮次分组。
- **目的**：直观展示各阶段的持续时间，识别瓶颈（如 Prefill 过长或 Decode 过慢）。

### 14. 跨轮次的时间对比
- **可视化**：分组柱状图，对比不同轮次的 Prefill 时间、Decode 时间、总时间。
- **目的**：分析多轮对话中上下文保持对性能的影响。

---

## 七、异常检测与数据质量验证

### 15. 功率波动性分析
- **可视化**：计算每个实验功率序列的标准差，绘制直方图，识别波动过大的异常实验。
- **目的**：剔除因硬件或环境干扰导致的数据异常，保证分析可靠性。

### 16. 事件完整性检查
- **可视化**：统计每个实验的事件数量，检查是否所有关键事件都存在（如 first_token 缺失可能导致 TTFT 无法计算）。
- **目的**：验证数据记录的完整性，发现可能的实验故障。

---

## 八、跨实验对比分析

### 17. 多模型同一任务功耗曲线叠加
- **可视化**：在同一张图上绘制不同模型/量化在相同任务下的 GPU 功率曲线，对齐时间轴（以推理开始为 0 点）。
- **目的**：直观对比不同配置的功耗特征，如峰值功耗、稳态功耗、生成阶段时长。

### 18. 任务类型对功耗波形的影响
- **可视化**：按任务类型分组，绘制平均功率曲线（归一化时间轴）。
- **目的**：识别不同任务（如代码生成 vs 创意写作）的功耗模式差异。
