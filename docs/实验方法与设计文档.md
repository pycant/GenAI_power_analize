## 研究目标

### 核心研究问题

在给定的硬件资源和计算预算下，构建全面、客观的 GenAI（生成式人工智能）模型能效评级体系，通过多维效质比评估方法，为学术界和工业界提供标准化的模型评估工具，促进 AI 技术的可持续发展。

### 具体目标

1. **性能-效率权衡分析**
   - 量化模型在质量、延迟和能耗三个维度的权衡关系
   - 识别在不同约束条件下的最优模型配置

2. **任务特异性研究**
   - 评估模型在不同任务类型上的表现差异
   - 分析任务特性对模型性能的影响

3. **量化方式影响评估**
   - 对比不同量化精度（4bit, 8bit, Q4_K_M）的性能差异
   - 量化对质量和效率的影响机制

4. **公平性分析**
   - 评估模型在不同任务上的表现公平性
   - 识别系统性偏差和不均衡现象

5. **能效评级体系构建**
   - 建立标准化的能效评级标准
   - 为不同应用场景推荐最优模型

### 研究假设

**H1**: 模型参数量与能耗呈正相关，但与质量的关系非线性  
**H2**: 量化会降低模型质量，但能显著提升效率  
**H3**: 不同任务类型对模型的质量和效率要求存在显著差异  
**H4**: 存在帕累托最优模型集合，在质效比上优于其他模型  
**H5**: 模型在不同任务上的表现存在公平性问题

## 实验设计原则

### 1. 控制变量原则

- **硬件环境固定**: 所有实验在同一硬件平台上进行
- **软件版本统一**: 使用相同版本的推理引擎和依赖库
- **参数标准化**: 采用统一的生成参数（temperature, top_p等）

### 2. 可重复性原则

- **随机种子固定**: 设置固定的随机种子（SEED=42）
- **实验记录完整**: 记录所有配置参数和环境信息
- **数据版本管理**: 使用 Git 管理实验配置和结果

### 3. 全面性原则

- **多模型覆盖**: 包含不同系列、不同参数量的模型
- **多任务类型**: 涵盖 7 种典型 NLP 任务
- **多维度评估**: 同时评估性能、效率和质量

### 4. 公平性原则

- **统一评估标准**: 所有模型使用相同的评估指标
- **任务平衡**: 每个任务类型的样本数量均衡
- **避免偏差**: 使用多样化的测试用例

### 5. 实用性原则

- **真实场景**: 测试用例来自实际应用场景
- **可操作性**: 评估结果可指导实际部署决策
- **可扩展性**: 实验框架易于扩展到新模型和任务

## 任务设计

### 任务类型分类

根据 NLP 任务的特性和应用场景，设计 7 种任务类型：

#### 1. 代码生成 (Code 
- unique_token_ratio: 独特词汇比例
- total_rhetorical_devices: 修辞手法总数
- perplexity: 语言模型困惑度

#### 3. 数学推理 (Math Reasoning)

**任务描述**: 解决数学问题并给出推理过程

**评估重点**:
- 答案准确性（精确匹配）
- 推理完整性
- 计算步骤清晰度

**示例提示**:
```
问题：一个长方形的长是宽的2倍，周长是36厘米，求面积。
要求：
1. 写出完整的解题步骤
2. 给出最终答案
```

**质量指标**:
- exact_match: 精确匹配率
- numerical_match: 数值匹配率
- has_reasoning: 是否包含推理过程
- step_count: 推理步骤数

#### 4. 问答 (Question Answering)

**任务描述**: 回答事实性或推理性问题

**评估重点**:
- 答案准确性
- 回答完整性
- 技术术语使用

**示例提示**:
```
问题：什么是深度学习？它与机器学习有什么区别？
要求：
1. 定义清晰
2. 对比准确
3. 举例说明
```

**质量指标**:
- confidence_score: 置信度得分
- technical_term_density: 技术术语密度
- reasoning_steps: 推理步骤数
- has_examples: 是否包含示例

#### 5. 逻辑推理 (Reasoning)

**任务描述**: 进行逻辑推理并得出结论

**评估重点**:
- 结论正确性
- 推理完整性
- 逻辑连贯性

**示例提示**:
```
前提：
1. 所有的猫都是哺乳动物
2. 所有的哺乳动物都需要呼吸
3. 小花是一只猫

问题：小花需要呼吸吗？请给出推理过程。
```

**质量指标**:
- conclusion_correct: 结论正确性
- completeness_score: 推理完整性
- coherence_score: 逻辑连贯性
- premise_usage_rate: 前提使用率

#### 6. 文本摘要 (Summarization)

**任务描述**: 将长文本压缩为简洁摘要

**评估重点**:
- 信息保留（ROUGE）
- 语义相似度（BERTScore）
- 压缩比适中

**示例提示**:
```
请将以下文本总结为100字以内的摘要：

[原文内容...]

要求：
1. 保留关键信息
2. 语言简洁
3. 逻辑清晰
```

**质量指标**:
- rouge_1/2/l_f1: ROUGE F1 分数
- bertscore_f1: BERTScore F1 分数
- bartscore_avg: BARTScore 平均分
- compression_ratio: 压缩比

#### 7. 翻译 (Translation)

**任务描述**: 在不同语言间进行翻译

**评估重点**:
- 翻译准确性（BLEU）
- 语义保真度（BERTScore）
- 流畅性（chrF）

**示例提示**:
```
将以下英文翻译成中文：

"Artificial intelligence is transforming the way we live and work."

要求：
1. 准确传达原意
2. 符合中文表达习惯
3. 术语翻译准确
```

**质量指标**:
- bleu_1/2/4: BLEU 分数
- bertscore_f1: BERTScore F1 分数
- chrf: 字符级 F 分数
- length_ratio: 长度比

```python
class ResourceMonitor:

        初始化监控器

        self.data = {

            'mem_used_mb': [],
            'gpu_util': [],
            'gpu_mem_mb': [],
            'gpu_power_w': [],
```

## 评估指标体系

### 性能指标

#### 1. 吞吐量 (Throughput)

**定义**: 单位时间内生成的 token 数量

**计算公式**:

```text
throughput = total_tokens / total_time_seconds
```

**单位**: tokens/s

**优化方向**: 越高越好 ↑

#### 2. 延迟 (Latency)

**定义**: 完成一次推理所需的总时间

**计算公式**:

```text
latency = end_time - start_time
```

**单位**: 秒 (s)

**优化方向**: 越低越好 ↓

#### 3. 首 Token 时间 (TTFT)

**定义**: 从输入到生成第一个 token 的时间

**计算公式**:

```text
ttft = first_token_time - start_time
```

**单位**: 秒 (s)

**优化方向**: 越低越好 ↓

**意义**: 反映用户感知的响应速度

#### 4. 每 Token 时间 (TPOT)

**定义**: 生成每个 token 的平均时间

**计算公式**:

```text
tpot = decode_time / (output_tokens - 1)
```

**单位**: 秒 (s)

**优化方向**: 越低越好 ↓

### 效率指标

#### 1. GPU 能耗 (GPU Energy)

**定义**: GPU 在推理过程中消耗的总能量

**计算方法**: 梯形积分法

```python
def calculate_energy(timestamps, power_values):
    energy = 0
    for i in range(len(timestamps) - 1):
        dt = timestamps[i+1] - timestamps[i]
        avg_power = (power_values[i] + power_values[i+1]) / 2
        energy += avg_power * dt
    return energy
```

**单位**: 焦耳 (J)

**优化方向**: 越低越好 ↓

#### 2. 增量能耗 (Incremental Energy)

**定义**: 推理过程相对于空闲状态的额外能耗

**计算公式**:

```text
E_inc = E_total - P_idle × total_time
```

其中:

- `E_total`: 总能耗
- `P_idle`: 空闲功耗（基线测量）
- `total_time`: 推理总时间

**单位**: 焦耳 (J)

**优化方向**: 越低越好 ↓

#### 3. 每 Token 能耗 (Energy per Token)

**定义**: 生成每个 token 的平均能耗

**计算公式**:

```text
E_token = E_inc / output_tokens
```

**单位**: J/token

**优化方向**: 越低越好 ↓

#### 4. 能效比 (Energy Efficiency)

**定义**: 单位能耗的 token 产出

**计算公式**:

```text
TPJ = total_tokens / E_total
```

**单位**: tokens/J

**优化方向**: 越高越好 ↑

#### 5. 功率效率 (Power Efficiency)

**定义**: 单位功耗的吞吐量

**计算公式**:

```text
PPW = throughput / P_avg
```

**单位**: tokens/(s·W)

**优化方向**: 越高越好 ↑

### 质量指标

质量指标根据任务类型不同而不同，详见《数据预处理文档.md》中的质量评估部分。

### 复合指标

#### 1. 效率得分 (Efficiency Score)

**定义**: 综合吞吐量、延迟和能耗的效率评分

**计算公式**:

```text
efficiency_score = 
    0.4 × norm_throughput + 
    0.3 × (1 - norm_latency) + 
    0.3 × (1 - norm_energy)
```

**归一化方法**: Min-Max Scaling（按任务分组）

**取值范围**: [0, 1]

**优化方向**: 越高越好 ↑

#### 2. 质效比 (Quality-Efficiency Ratio)

**定义**: 质量与效率的综合平衡指标

**计算公式**:

```text
qe_ratio = (norm_quality + ε) / (1 + ε - efficiency_score)
```

其中 `ε = 0.01` 为微小偏置，避免分母为零

**取值范围**: (0, +∞)

**优化方向**: 越高越好 ↑

**解释**:

- 分子越大，质量越高
- 分母越小，效率越高
- 比值越大，质效比越优

## 实验流程

### 完整实验流程

```text
1. 实验初始化
   ├── 加载配置文件 (config.py, test_cases.json)
   ├── 检查 Ollama 服务状态
   ├── 初始化资源监控器 (ResourceMonitor)

2. 基线测量
   ├── 运行 30 秒空闲监控
   ├── 记录基线功耗 (P_idle)
   └── 保存基线数据

3. 模型预热 (Warmup)
   ├── 发送简单提示词
   ├── 加载模型到内存/显存
   └── 丢弃预热结果

4. 实验执行循环
   For each test_case in test_cases:
     ├── 启动资源监控
     ├── 记录开始时间戳
     ├── 调用模型生成 (Ollama/HF API)
     ├── 记录首 token 时间 (TTFT)
     ├── 流式接收生成结果

     └── 保存原始数据 (raw)

   ├── 任务特定指标计算
   ├── BARTScore 评估 (如果有参考文本)
   └── 其他质量指标 (ROUGE, BLEU, BERTScore等)

   ├── 计算性能指标 (吞吐量、延迟、TTFT)

   └── 生成汇总数据 (summary)

   ├── 保存原始数据 (*_raw.json)
   ├── 保存汇总数据 (*_summary.json)
```

### 帕累托分析

**目的**: 识别在多目标优化中的帕累托最优解集

**方法**:

1. 定义优化目标（质量↑、延迟↓、能耗↓）
2. 计算帕累托前沿
3. 识别非支配解

```python
def is_pareto_efficient(costs):
    """
    找出帕累托最优解
    costs: n×m 矩阵，n个解，m个目标
    """
    is_efficient = np.ones(costs.shape[0], dtype=bool)
    for i, c in enumerate(costs):
        if is_efficient[i]:
            # 移除被当前解支配的解
            is_efficient[is_efficient] = np.any(
                costs[is_efficient] < c, axis=1
            )
            is_efficient[i] = True
    return is_efficient
```

## 常见问题与解决方案

### Q1: 实验中途中断怎么办？

**解决方案**:

- 实验框架支持断点续传
- 已完成的实验数据会保存
- 重新运行时跳过已完成的测试用例

### Q2: GPU 温度过高

**解决方案**:

- 降低实验频率，增加冷却时间
- 改善散热条件
- 降低 GPU 功耗限制

### Q3: 内存不足

**解决方案**:

- 使用更小的模型
- 启用模型量化（4bit）
- 减少批处理大小
- 关闭不必要的程序

### Q4: 结果不稳定

**解决方案**:

- 增加重复实验次数
- 检查系统后台进程
- 延长预热时间
- 固定随机种子

### Q5: BARTScore 计算失败

**解决方案**:

- 使用 `--skip-bartscore` 跳过
- 检查 CUDA 内存
- 使用 CPU 模式（较慢）
